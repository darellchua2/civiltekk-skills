## Human-Readable Replies

Every substantive reply — primary or subagent, all sessions — carries a plain-language essence a non-engineer can act on: for each finding/decision, one line stating what it affects (users, data, revenue, compliance, delivery dates) and why it matters, before the technical detail. Keep evidence precise (`file:line`, commands, diffs); humanize the prose around it — write like a person briefing a stakeholder, not a checklist. Apply `unslop-skill` patterns by default: no "delve", "tapestry", "not X but X", em-dash abuse, or similar AI-tell phrasing.

## Commits

Conventional Commits `type(scope): description`; atomic (split migration/model/schema/logic/tests); body ≤72 chars (commitlint may override); never mix style-only with logic. Granularity: `civiltekk-git-commits-skill` (semantic route).

## Memory Hygiene

Via `LEARNINGS/*.md` + the auto-inject manifest; full procedure in `continuous-learning-skill`.
- **Recall:** `search` scope `project`, limit 5, before any review/plan/debug; if empty, proceed silently.
- **Capture:** ONE 2-line `add` per non-trivial fix/decision (`error-solution`/`architecture`/`learned-pattern`) — never routine commits, secrets, PII, or file contents.
- **Commit:** standalone sessions commit each capture at write time — one `chore(learnings): <slug>` commit (body + the matching `.gitignore` negation appended at end of file) — never left dirty; push only when the session's flow pushes. `LEARNINGS/_index.md` is a local derived cache — never stage or commit it. Pipeline/plan runs never commit mid-phase — they land one trailing `chore(learnings)` commit at end of ticket. `scope=user` skips.
- **LEARNINGS manifest** is auto-injected per session by the local plugin (ported to the v2 plugin API — active); `glob`+`read()` of `LEARNINGS/` remains the fallback.
- Scope: `project` = repo learnings; `user` = cross-project preferences.

## Skill & Agent Installation

User-scope installs and updates of civiltekk catalog entries (skills, subagents, their dep-shipped plugins) route through the `install-assistant-skill` skill when present — dry-run before every write, never hand-copy files from a skill repo, never hand-edit installed copies (fix at source, then the installer's `update`). Search the catalog before authoring anything new; a match may already ship.
